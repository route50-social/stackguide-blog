ChatGPT vs 로컬 LLM: 내 컴퓨터에서 AI를 돌리는 이유

ChatGPT 같은 클라우드 AI와 내 컴퓨터에서 돌리는 로컬 LLM을 개인정보, 비용, 성능 세 가지 기준으로 비교하고, 2026년 11월 기준 공식 문서와 요금표로 언제 로컬이 유리한지 정리합니다.

ChatGPT를 쓰다 보면 한 번쯤 멈칫하는 순간이 있습니다. 회사 코드를 붙여 넣어도 되는지, 고객 명단이 담긴 엑셀을 올려도 되는지 같은 순간입니다. 이런 고민 끝에 “아예 내 컴퓨터에서 AI를 돌리면 되지 않나” 하고 로컬 LLM을 찾아보게 됩니다.

용어 풀이

  • LLM(Large Language Model, 대규모 언어 모델): 아주 많은 글을 학습해 문장을 이어 쓰는 큰 규모의 언어 모델입니다. ChatGPT도 LLM을 바탕으로 만든 서비스입니다.
  • 로컬 LLM: 클라우드 서비스가 아니라 내 PC나 서버에서 직접 실행하는 LLM입니다. 모델 파일을 내려받아 내 컴퓨터의 메모리와 그래픽카드로 계산합니다.

결론부터 말하면, 로컬 LLM은 ChatGPT를 대신하는 물건이라기보다 쓰임새가 다른 도구입니다. 데이터가 내 컴퓨터 밖으로 나가지 않고 쓸수록 돈이 더 들지 않는다는 장점이 있지만, 답의 품질과 편의 기능은 대체로 클라우드 쪽이 앞섭니다. 이 글에서는 둘을 개인정보, 비용, 성능 세 가지 기준으로 나눠 비교하고, 어떤 상황에서 로컬이 유리한지 정리합니다. 요금과 정책은 2026-11-14에 OpenAI와 Ollama의 공식 페이지에서 확인한 값입니다.

같은 질문, 계산하는 곳이 다릅니다

두 방식의 차이는 결국 “모델이 어디서 계산되느냐”에서 나옵니다. ChatGPT에 질문을 입력하면 그 글은 인터넷을 거쳐 OpenAI의 데이터센터로 가고, 거기서 모델이 답을 만들어 돌려보냅니다. 로컬 LLM은 질문 입력부터 답 생성까지 전부 내 컴퓨터 안에서 일어납니다.

그림 1. 클라우드 AI와 로컬 LLM에서 질문이 처리되는 위치 (자료: OpenAI 데이터 제어 문서, Ollama FAQ, 2026-11-14 확인)

용어 풀이

  • HTTPS(Hypertext Transfer Protocol Secure): 웹 브라우저와 서버가 주고받는 내용을 암호화하는 통신 방식입니다. 전송 중에 엿보기는 어렵게 하지만, 받는 쪽 서버는 내용을 그대로 읽습니다.
  • Ollama(올라마): 내 컴퓨터에서 LLM을 내려받아 실행하고, 다른 프로그램이 HTTP API로 쓸 수 있게 해 주는 오픈 소스 도구입니다.

이 그림 하나에서 장단점이 대부분 갈립니다. 데이터가 밖으로 나가느냐는 개인정보 문제로, 누구의 장비로 계산하느냐는 비용과 성능 문제로 이어집니다.

개인정보: 학습 여부와 보관은 별개의 문제입니다

클라우드 AI를 걱정할 때 가장 먼저 떠올리는 것은 “내 대화가 모델 학습에 쓰이느냐”입니다. OpenAI의 답은 요금제마다 다릅니다.

  • 개인용 ChatGPT(Free, Go, Plus, Pro): ChatGPT 요금 비교표의 개인정보 항목에는 네 요금제 모두 “콘텐츠가 모델 학습에 사용됨(Content is used to train our models)“에 “옵트아웃 가능(Opt-out available)“이라고 적혀 있습니다. 기본으로는 학습에 쓰일 수 있고, 원하지 않으면 설정에서 직접 꺼야 한다는 뜻입니다.
  • ChatGPT Business: 소개 페이지에 “데이터는 모델 학습에 절대 사용되지 않는다(Your data is never used for training our models)“고 적혀 있습니다.
  • OpenAI API: 개발자 문서는 2023년 3월 1일부터 API로 보낸 데이터를 모델 학습에 쓰지 않는다고 밝힙니다. 사용자가 명시적으로 공유에 동의한 경우는 예외입니다.

용어 풀이

  • 옵트아웃(Opt-out): 기본으로 켜져 있는 기능을 사용자가 직접 거부해 끄는 방식입니다. 반대로 사용자가 동의해야 켜지는 방식은 옵트인(Opt-in)이라고 합니다.
  • API(Application Programming Interface): 프로그램끼리 기능을 주고받는 약속된 창구입니다. 여기서는 채팅 화면 대신 내 프로그램이 OpenAI 모델을 호출하는 통로를 말합니다.

그런데 학습에 쓰지 않는다는 것과 데이터를 보관하지 않는다는 것은 다른 이야기입니다. 같은 API 문서에 따르면 OpenAI는 악용을 막기 위한 모니터링 로그를 기본으로 만들고 최대 30일 동안 보관합니다. 법적으로 더 오래 보관해야 하는 경우는 예외입니다. 이 로그에서 내용을 빼 주는 ZDR은 OpenAI의 사전 승인을 받은 고객만 쓸 수 있고, 엔드포인트마다 적용 여부도 다릅니다.

용어 풀이

  • ZDR(Zero Data Retention, 데이터 무보존): API로 보낸 내용을 악용 모니터링 로그에도 남기지 않도록 하는 OpenAI의 제어 옵션입니다. 승인을 받은 고객만 쓸 수 있습니다.

정리하면, 클라우드 AI에서 질문은 어떤 요금제든 일단 사업자 서버에 도착합니다. 학습 제외나 보관 기간은 그다음에 정해지는 정책입니다. 회사 규정이 “고객 정보는 외부 서비스로 보내지 않는다”처럼 전송 자체를 막고 있다면, 학습 설정을 껐더라도 규정을 지킨 것이 아닐 수 있습니다. 로컬 LLM이 가장 확실한 답이 되는 지점이 여기입니다.

로컬이라도 확인할 것

Ollama FAQ는 “로컬에서 실행하면 우리는 프롬프트나 데이터를 보지 않는다”고 설명합니다. 다만 Ollama에는 외부 서버에서 돌아가는 클라우드 모델도 함께 있습니다. 2026-11-14에 Ollama 모델 페이지를 확인해 보니 gpt-oss:20b와 나란히 gpt-oss:20b-cloud라는 태그가 있었습니다. 이런 모델을 고르면 질문이 Ollama 서버에서 처리됩니다. FAQ는 클라우드 모델의 질문과 답을 저장하거나 학습에 쓰지 않는다고 밝히지만, 데이터가 밖으로 나간다는 점에서는 클라우드 AI와 같습니다.

확실히 로컬로만 쓰고 싶다면 Ollama의 클라우드 기능을 끌 수 있습니다. FAQ에 따르면 OLLAMA_NO_CLOUD=1 환경 변수를 설정하거나 ~/.ollama/server.json에 disable_ollama_cloud를 true로 넣은 뒤 Ollama를 다시 시작하면 되고, 로그에 Ollama cloud disabled: true가 찍히는지로 확인합니다. 이렇게 하면 클라우드 모델과 웹 검색 기능도 함께 쓸 수 없게 됩니다.

# 실행 위치: 로컬 PC (macOS·Linux 터미널 기준)
# 전제: Ollama가 설치되어 있고, 서버를 터미널에서 직접 실행하는 경우
# 이 글을 쓰며 직접 실행하지는 못했고, Ollama FAQ로 확인한 설정입니다.
OLLAMA_NO_CLOUD=1 ollama serve

네트워크 노출도 챙겨야 합니다. Ollama는 기본으로 127.0.0.1의 11434번 포트에서만 요청을 받아, 같은 컴퓨터 안에서만 접속할 수 있습니다. Ollama API 문서에 따르면 로컬 요청에는 API 키가 필요 없습니다. 그래서 다른 기기에서 쓰려고 OLLAMA_HOST로 주소를 바꿔 네트워크에 열면, 그 네트워크에 접속한 누구나 내 모델을 호출할 수 있게 됩니다. 외부에서 써야 한다면 방화벽으로 접속할 수 있는 기기를 제한하고, 인증을 거는 리버스 프록시나 VPN 뒤에 두는 편이 안전합니다.

용어 풀이

  • 127.0.0.1(루프백 주소): 컴퓨터가 자기 자신을 가리키는 주소입니다. 여기에만 열린 서비스는 같은 컴퓨터 안의 프로그램만 접속할 수 있습니다.
  • 리버스 프록시(Reverse Proxy): 외부 요청을 먼저 받아 인증·암호화 같은 처리를 한 뒤 안쪽 서비스로 넘겨 주는 중간 서버입니다.
  • VPN(Virtual Private Network, 가상 사설망): 인터넷 위에 암호화된 통로를 만들어, 멀리 있는 기기를 같은 내부 네트워크에 있는 것처럼 연결하는 방식입니다.

비용: 정액, 종량제, 그리고 장비값

비용은 구조부터 다릅니다. ChatGPT 웹·앱은 요금제별 정액 구독이고, 개발자가 프로그램에서 부르는 API는 쓴 만큼 내는 종량제입니다. 로컬 LLM은 사용료가 없는 대신 장비를 먼저 사야 하고 전기를 씁니다.

용어 풀이

  • 종량제: 사용한 양에 비례해 요금을 내는 방식입니다. LLM API는 주고받은 토큰 수로 요금을 매깁니다.
  • 토큰(Token): 언어 모델이 글을 처리하는 기본 단위입니다. 단어 하나일 수도, 단어의 일부나 글자 하나일 수도 있습니다.

ChatGPT 구독료는 요금 페이지가 지역과 결제 환경에 따라 다르게 표시되어, 이 글에서는 금액을 적지 않습니다. 가입 전에 요금 페이지에서 내 계정 기준 금액을 직접 확인하세요. 정액 구독은 많이 쓸수록 이득이지만, 요금제마다 사용량 한도가 있다는 점도 함께 봐야 합니다.

API는 요금표가 공개되어 있어 계산해 볼 수 있습니다. 2026-11-14 OpenAI API 요금 페이지의 표준(Standard) 처리 기준 가격 가운데 세 모델을 골랐습니다.

모델 입력 100만 토큰당 출력 100만 토큰당
gpt-6-astra $10.00 $50.00
gpt-6.1-terra $1.00 $5.00
gpt-6-luna $0.10 $0.50

표 1. OpenAI API 표준 처리 요금 일부 (자료: OpenAI API Pricing, 2026-11-14 확인, 미국 달러, 짧은 컨텍스트 기준)

하루 100번 질문하고 한 번에 입력 1,000토큰, 출력 500토큰을 쓴다고 가정해 보겠습니다. 30일이면 입력 300만 토큰, 출력 150만 토큰입니다. gpt-6.1-terra로는 3 × $1 + 1.5 × $5 = $10.50, gpt-6-luna로는 $1.05, gpt-6-astra로는 $105가 나옵니다. 같은 사용량이라도 모델 선택에 따라 100배 차이가 납니다. 같은 요금 페이지에는 결과를 늦게 받는 대신 가격을 절반으로 낮추는 Batch 처리 요금도 따로 있습니다.

여기서 흔히 놓치는 점이 있습니다. API로 대화를 이어 가면 앞선 대화를 매번 다시 입력으로 보내는 경우가 많아, 대화가 길어질수록 입력 토큰이 빠르게 늘어납니다. 위 계산은 질문마다 새로 시작하는 단순한 경우입니다.

로컬 LLM의 비용은 장비와 전기입니다. 이미 쓸 만한 그래픽카드가 있다면 추가 비용은 거의 전기뿐입니다. 예를 들어 그래픽카드가 답을 만드는 동안 300W를 쓰고 하루 1시간 그렇게 돌린다고 가정하면 하루 0.3kWh, 한 달 9kWh입니다. 여기에 사는 곳의 전기 요금 단가를 곱하면 됩니다. 실제 소비 전력은 장비와 모델에 따라 크게 달라 직접 측정한 값이 아니라는 점은 감안해야 합니다.

새로 장비를 사야 한다면 계산이 달라집니다. 장비값을 한 달 API 비용으로 나누면 몇 달을 써야 본전인지 나오는데, 위처럼 한 달 몇 달러 수준으로 쓰는 사람이라면 장비값을 회수하기 어렵습니다. 비용만 보고 로컬을 고르는 것은 사용량이 아주 많거나, 이미 장비가 있을 때 의미가 있습니다.

성능: 같은 회사 모델이라도 크기가 다릅니다

로컬 LLM을 처음 써 보면 대부분 답의 품질에서 실망합니다. 이유는 단순합니다. 클라우드 AI의 최상위 모델은 데이터센터의 고성능 GPU 여러 대에서 돌아가지만, 로컬 LLM은 내 컴퓨터 메모리에 들어가는 크기로 골라야 합니다.

OpenAI가 공개한 gpt-oss가 좋은 예입니다. 모델 파일을 누구나 내려받아 쓸 수 있도록 Apache 2.0 라이선스로 공개했고, GitHub 저장소 설명에 따르면 크기가 두 가지입니다.

모델 전체 파라미터 활성 파라미터 실행 조건 (공식 설명) Ollama 파일 크기
gpt-oss-20b 21B 3.6B 16GB 메모리 안에서 실행 14GB
gpt-oss-120b 117B 5.1B 80GB GPU 한 장(H100 등) 65GB

표 2. gpt-oss 두 모델의 크기와 실행 조건 (자료: openai/gpt-oss GitHub 저장소, Ollama gpt-oss 모델 페이지, 2026-11-14 확인)

용어 풀이

  • 오픈 웨이트(Open Weight): 학습을 마친 모델의 파라미터 파일을 공개해 누구나 내려받아 실행할 수 있게 한 모델입니다. 학습 데이터나 학습 코드까지 공개한다는 뜻은 아닙니다.
  • MoE(Mixture of Experts, 전문가 혼합): 모델의 일부를 여러 “전문가” 묶음으로 나눠 두고, 입력마다 몇 개만 골라 계산하는 구조입니다. 전체 파라미터보다 활성 파라미터가 훨씬 적은 이유입니다.
  • VRAM(Video RAM, 그래픽 메모리): 그래픽카드에 달린 메모리입니다. 모델이 VRAM에 전부 올라가면 빠르게 돌고, 넘치면 일부가 일반 메모리로 밀려나 느려집니다.

일반 PC에서 현실적으로 돌릴 수 있는 쪽은 20b입니다. 120b는 80GB짜리 데이터센터용 GPU를 기준으로 설명되어 있습니다. 두 모델 모두 MoE 구조라 한 번에 계산하는 파라미터는 적지만, 파일 전체는 메모리에 올라가 있어야 합니다. 모델 이름만 보고 필요한 메모리를 어림하는 방법은 모델 이름 읽는 법에서 자세히 다뤘습니다.

품질 말고도 차이가 있습니다. ChatGPT는 웹 검색, 파일 분석, 이미지 생성 같은 기능을 서비스에 묶어 제공하지만, 로컬 모델은 기본적으로 글을 주고받는 모델 하나입니다. 최신 정보를 찾거나 문서를 읽히려면 그 기능을 직접 붙여야 합니다. 속도도 내 장비에 달려 있어서, 모델이 VRAM에 다 들어가지 않으면 답이 눈에 띄게 느려집니다.

반대로 로컬이 앞서는 성능도 있습니다. 인터넷이 끊겨도 돌아가고, 서비스 장애나 사용량 한도에 걸리지 않으며, 모델을 업데이트하지 않는 한 같은 모델이 계속 같은 방식으로 동작합니다. 매일 같은 형식의 문서를 처리하는 자동화라면 이 일관성이 품질 몇 점보다 중요할 수 있습니다.

언제 로컬이 유리할까

지금까지의 내용을 상황별로 묶으면 다음과 같습니다.

상황 더 맞는 쪽 이유
외부 전송이 금지된 사내 문서·고객 정보를 다룸 로컬 데이터가 내 컴퓨터 밖으로 나가지 않음
인터넷이 없거나 불안정한 환경 로컬 오프라인으로 동작
같은 작업을 대량으로 반복하는 자동화 로컬 검토 사용량이 늘어도 사용료가 없고, 모델이 바뀌지 않음
어려운 추론, 긴 글쓰기, 최신 정보 검색 클라우드 더 큰 모델과 검색 기능을 바로 씀
가끔 쓰고 장비가 없음 클라우드 장비값을 회수하기 어려움
AI가 어떻게 동작하는지 직접 배워 보고 싶음 로컬 모델 선택, 양자화, 컨텍스트 설정을 직접 바꿔 볼 수 있음

표 3. 상황별로 더 맞는 방식 (필자 정리)

꼭 하나만 고를 필요도 없습니다. 민감한 자료를 요약하거나 분류하는 일은 로컬 모델에 맡기고, 공개된 자료로 어려운 질문을 할 때는 ChatGPT를 쓰는 식으로 나눠 쓰는 사람이 많습니다. 시작은 가볍게 해 보면 됩니다. 지금 가진 컴퓨터의 메모리 크기를 확인하고, 그 안에 들어가는 작은 모델 하나를 받아 평소 ChatGPT에 하던 질문을 똑같이 던져 보세요. 답을 나란히 놓고 비교해 보면 내 용도에서 로컬이 어디까지 쓸 만한지 금방 감이 옵니다.
