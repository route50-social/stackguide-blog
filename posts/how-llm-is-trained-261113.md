# LLM은 어떻게 만들어질까: 사전학습, 파인튜닝, RLHF

> LLM은 수조 개의 토큰으로 다음 토큰을 맞히는 사전학습, 질문과 모범 답안으로 답하는 법을 익히는 지도 파인튜닝, 사람이 더 좋아하는 답 쪽으로 다듬는 RLHF·DPO를 거쳐 만들어집니다. 같은 모델의 베이스판과 대화판을 직접 비교하며 단계마다 무엇이 달라지는지 살펴봅니다.

- 태그: LLM, 사전학습, 파인튜닝, SFT, RLHF, DPO, PPO, 강화학습, 보상모델, 베이스모델, 인스트럭션튜닝, 채팅템플릿, AI정렬, 다음토큰예측, 토큰, 파라미터, 환각, Qwen, AI기초, 입문

[지난 글](https://stackguide.route50.kr/posts/how-llm-writes-tokens-261113/)에서 LLM에 "대한민국의 수도는"이라는 글을 대화 형식 없이 그대로 넣어 봤습니다. 한 모델은 "서울입니다"라고 이어 썼지만, 다른 모델은 "대한민국의 수도는 어디인가요"라는 질문으로 문장을 끝냈습니다. LLM의 본업은 질문에 답하는 것이 아니라 주어진 글 뒤에 올 법한 글을 이어 쓰는 것이기 때문입니다.

> **용어 풀이**
>
> - **LLM(Large Language Model, 대규모 언어 모델):** 아주 많은 글을 학습해 문장을 이어 쓰는 큰 규모의 언어 모델입니다. ChatGPT, Claude, Gemini 같은 대화형 서비스의 중심에 있습니다.

그런데 ChatGPT나 Claude는 질문을 받으면 답을 하고, 답이 끝나면 알아서 멈추고, 위험한 부탁은 거절하기도 합니다. 글을 이어 쓰기만 하던 모델이 어떻게 이런 대화 상대가 될까요? 답은 학습을 한 번에 끝내지 않고 여러 단계로 나눠 진행한다는 데 있습니다. 먼저 엄청난 양의 글로 다음 토큰을 맞히는 사전학습을 하고, 그 모델에 질문과 모범 답안을 보여 주는 파인튜닝을 하고, 마지막으로 사람이 더 좋아하는 답 쪽으로 다듬는 RLHF 같은 과정을 거칩니다.

*(그림: 1 사전학습은 웹 문서, 책, 코드 등 수조 개의 토큰으로 다음 토큰 맞히기를 배워 베이스 모델이 되고, 2 지도 파인튜닝은 질문과 모범 답안 쌍으로 답안을 따라 쓰게 해 지시를 따르는 모델을 만들고, 3 선호 학습은 여러 답변의 비교와 순위로 더 나은 답 쪽으로 모델을 기울여 대화형 어시스턴트를 만드는 흐름. 오른쪽으로 갈수록 데이터 양은 줄고 학습용으로 따로 만든 데이터가 많아집니다.)*

*그림 1. LLM이 만들어지는 세 단계 (자료: InstructGPT 논문, Llama 3·Qwen2.5 기술 보고서, 2026-11-13 확인)*

> **용어 풀이**
>
> - **사전학습(Pre-training):** 특정 작업을 정하지 않고 아주 많은 글로 언어 자체를 먼저 배우는 단계입니다. 이 단계에서 만들어진 모델을 바탕으로 이후 학습을 이어 갑니다.
> - **파인튜닝(Fine-tuning, 미세 조정):** 이미 학습된 모델을 특정 목적에 맞는 데이터로 추가 학습하는 일입니다.
> - **RLHF(Reinforcement Learning from Human Feedback, 사람 피드백 기반 강화학습):** 사람이 여러 답변을 비교해 매긴 평가를 바탕으로 모델이 더 선호되는 답을 내도록 강화학습으로 조정하는 방법입니다.

이 글에서는 세 단계가 각각 무엇을 바꾸는지 차례로 살펴봅니다. 회사마다 세부 방법은 다르고 모두 공개되지도 않으므로, 과정을 상세히 공개한 OpenAI의 InstructGPT 논문(2022)과 Meta의 Llama 3, 알리바바의 Qwen2.5 기술 보고서를 주된 근거로 삼았습니다.

## 먼저 직접 비교해 보기: 같은 모델의 두 판

단계별 차이를 가장 쉽게 확인하는 방법은 같은 모델의 "사전학습만 끝난 판"과 "그 뒤 단계까지 거친 판"을 나란히 돌려 보는 것입니다. 알리바바의 Qwen2.5는 두 판을 함께 공개합니다. 모델 카드에 따르면 `Qwen2.5-0.5B`는 학습 단계가 "사전학습"인 베이스 모델이고, `Qwen2.5-0.5B-Instruct`는 "사전학습과 후속 학습"을 거친 모델입니다. 둘 다 파라미터가 약 4억 9천만 개(0.49B)로 크기와 구조가 같습니다. 베이스 모델의 카드에는 "베이스 언어 모델을 대화에 쓰는 것은 권장하지 않는다"는 안내도 있습니다.

> **용어 풀이**
>
> - **파라미터(Parameter, 매개변수):** 학습 과정에서 조정되는 모델 내부의 숫자입니다. 모델이 데이터에서 배운 내용은 결국 이 숫자들에 담깁니다.
> - **베이스 모델(Base Model):** 사전학습만 마친 모델입니다. 파운데이션 모델, 사전학습 모델이라고도 부르며, 이름에 `Instruct`나 `Chat`이 붙은 모델은 보통 여기에 후속 학습을 더한 판입니다.

측정 환경은 Windows 11 Pro, Python 3.9.13, PyTorch 2.8.0(CPU 판), Transformers 4.49.0입니다. 두 모델을 Hugging Face에서 내려받아 같은 질문을 두 가지 방식으로 넣었습니다. 하나는 질문 글을 그대로 넣는 방식이고, 다른 하나는 모델에 딸린 채팅 템플릿으로 질문을 대화 형식으로 감싸 넣는 방식입니다. 무작위성을 없애려고 매번 확률이 가장 높은 토큰만 고르는 그리디 디코딩으로 최대 80토큰까지 생성했습니다. Instruct 모델에 딸린 기본 생성 설정은 샘플링과 반복 억제(`repetition_penalty` 1.1)를 켜 두지만, 두 모델을 같은 조건으로 비교하려고 이 설정을 끄고 멈춤 토큰도 똑같이 맞췄습니다.

> **용어 풀이**
>
> - **채팅 템플릿(Chat Template):** 대화 내용을 모델이 학습한 형식의 글로 바꾸는 틀입니다. 누가 말했는지 표시하는 역할 표시와 대화의 시작·끝을 알리는 특별한 토큰을 붙입니다.
> - **그리디 디코딩(Greedy Decoding):** 매 위치에서 확률이 가장 높은 토큰만 고르는 생성 방식입니다. 같은 입력이면 같은 결과가 나옵니다.

```py
# 실행 위치: 로컬 PC (Windows 11 Pro, Python 3.9.13, torch 2.8.0+cpu, transformers 4.49.0)
# 전제: pip install torch transformers 로 설치. 처음 실행하면 모델 파일(각 약 1GB)을 내려받습니다.
from transformers import AutoModelForCausalLM, AutoTokenizer

question = "비밀번호를 안전하게 저장하는 방법 세 가지만 알려 줘."

for name in ["Qwen/Qwen2.5-0.5B", "Qwen/Qwen2.5-0.5B-Instruct"]:
    tok = AutoTokenizer.from_pretrained(name)
    model = AutoModelForCausalLM.from_pretrained(name)
    chat = tok.apply_chat_template(
        [{"role": "user", "content": question}],
        tokenize=False, add_generation_prompt=True,
    )
    for text in [question, chat]:  # 질문 그대로, 대화 형식으로 감싼 질문
        ids = tok(text, return_tensors="pt")
        out = model.generate(
            **ids, max_new_tokens=80, do_sample=False, repetition_penalty=1.0,
            temperature=None, top_p=None, top_k=None,
            eos_token_id=[151643, 151645],  # <|endoftext|>, <|im_end|>
        )
        print(name, repr(tok.decode(out[0, ids["input_ids"].shape[1]:])))
```

*표 1. 같은 질문에 대한 베이스 모델과 Instruct 모델의 응답 (측정: Qwen2.5-0.5B·Qwen2.5-0.5B-Instruct, 그리디 디코딩, 반복 억제 끔, 최대 80토큰, 2026-11-13)*

베이스 모델에 질문을 그대로 넣으면 답을 하지 않습니다. 질문 뒤에 게시판 분류처럼 보이는 " - IT연애"를 붙이고 같은 질문을 계속 되풀이합니다. 인터넷 게시판이나 검색어 목록에서 이런 문장이 어떻게 이어지는지를 흉내 낸 모습입니다. 대화 형식으로 감싸 주면 첫 문장은 답처럼 시작하지만, 곧 의미 없는 단어를 반복하며 무너지고 대화가 끝났다는 표시도 끝내 내놓지 못합니다. 반면 Instruct 모델은 "여러 가지가 있습니다"로 시작해 번호와 굵은 글씨로 정리한 답변 형식을 갖춥니다. "대한민국의 수도는"을 대화 형식으로 넣었을 때는 "대한민국의 수도는 서울입니다."까지 쓰고 대화 끝 표시를 내놓아 열한 토큰 만에 멈췄습니다.

다른 질문에서도 차이는 비슷했습니다. 대화 형식에서 첫 토큰의 확률을 비교하면 차이가 숫자로도 보입니다.

| 비밀번호를 안전하게 저장하는 방법 세 가지만 알려 줘. | `비` 67.5% | `비` 93.5% |

*표 2. 대화 형식으로 넣었을 때 첫 토큰으로 가장 확률이 높았던 후보 (측정: Qwen2.5-0.5B·Qwen2.5-0.5B-Instruct, 2026-11-13. 확률은 소수 첫째 자리에서 반올림)*

베이스 모델은 대화 형식의 글을 받아도 다음에 무엇이 와야 할지 확신하지 못하고 확률이 여러 후보에 흩어집니다. 리눅스 질문에서는 1위 후보가 질문과 상관없는 `atives`였고 확률도 3.1%에 그쳤습니다. Instruct 모델은 "질문을 받은 어시스턴트가 답을 시작하는 자리"가 무엇인지 알고 있어서 답의 첫머리에 확률이 몰립니다. 두 모델은 구조도 크기도 같습니다. 달라진 것은 사전학습 뒤에 이어진 학습뿐입니다.

하나 더 눈여겨볼 점이 있습니다. Instruct 모델의 답은 형식은 그럴듯하지만 내용이 틀렸습니다. OWASP의 비밀번호 저장 지침은 되돌릴 수 있는 암호화가 아니라 한 방향으로만 계산되는 해시를 쓰라고 하며, Argon2id를 첫 번째로 권합니다. 암호화를 "가장 기본적인 방법"으로 꼽은 이 답은 보안 지침과 어긋납니다. 0.5B라는 아주 작은 모델이기도 하지만, 후속 학습이 "답하는 형식"은 가르쳐도 모델이 모르는 지식까지 채워 주지는 않는다는 점을 보여 주는 예이기도 합니다. 이 이야기는 아래에서 다시 다룹니다.

## 1단계 사전학습: 세상의 글로 다음 토큰 맞히기

사전학습은 [지난 글](https://stackguide.route50.kr/posts/how-llm-writes-tokens-261113/)에서 본 "다음 토큰 예측"을 엄청난 규모로 연습하는 단계입니다. 웹 문서, 책, 코드 같은 글을 토큰으로 자른 뒤, 앞부분을 보여 주고 바로 다음 토큰을 맞히게 합니다. 틀린 만큼 파라미터를 조금씩 고치는 일을 수조 개의 토큰에 대해 반복합니다. 정답이 글 안에 이미 들어 있으므로 사람이 따로 정답을 달아 줄 필요가 없습니다. 이렇게 데이터 스스로 정답을 제공하는 학습을 자기지도 학습이라고 합니다.

> **용어 풀이**
>
> - **토큰(Token):** 언어 모델이 글을 처리하는 기본 단위입니다. 단어 하나일 수도, 단어의 일부나 글자 하나일 수도 있습니다.
> - **다음 토큰 예측(Next-token Prediction):** 앞의 토큰들을 보고 바로 다음에 올 토큰의 확률을 계산하는 일입니다. LLM의 사전학습 목표이자 글을 쓰는 방식입니다.
> - **자기지도 학습(Self-supervised Learning):** 사람이 정답을 달지 않고, 데이터의 일부를 가린 뒤 나머지로 가린 부분을 맞히게 하는 방식으로 정답을 데이터 자체에서 얻는 학습 방법입니다.

규모는 상상하기 어려울 만큼 큽니다. Meta의 Llama 3 기술 보고서에 따르면 가장 큰 405B 모델은 약 15.6조(15.6T) 개의 토큰으로 사전학습했고, 데이터는 대략 일반 지식 50%, 수학·추론 25%, 코드 17%, 다국어 8%로 섞었습니다. 학습에는 H100 GPU를 최대 16,000개까지 썼고, 계산량은 3.8×10²⁵ FLOPs였습니다. Qwen2.5 기술 보고서는 사전학습 데이터를 이전 세대의 7조 토큰에서 18조 토큰으로 늘렸다고 밝힙니다.

> **용어 풀이**
>
> - **GPU(Graphics Processing Unit, 그래픽 처리 장치):** 원래 그래픽 계산용으로 만든 칩이지만, 같은 계산을 대량으로 동시에 처리하는 데 강해 AI 모델 학습에 주로 쓰입니다.
> - **FLOPs(Floating-point Operations, 부동소수점 연산 횟수):** 실수 계산을 몇 번 했는지 센 값입니다. 모델 학습에 든 계산량을 비교할 때 씁니다.

이 단계를 마친 베이스 모델은 도서관의 책을 엄청나게 읽은 사람과 비슷합니다. 문법과 어휘, 여러 분야의 사실, 코드 작성법까지 많은 것을 알고 있지만, 손님을 응대하는 방법은 배운 적이 없습니다. 그래서 질문을 받으면 그 질문이 실린 문서가 어떻게 이어지는지를 떠올려 이어 씁니다. 표 1에서 베이스 모델이 질문을 반복하거나 게시판 분류 같은 말을 붙인 것이 바로 그 모습입니다. 질문 다음에 답이 오는 문서도 학습 데이터에 많지만, 질문 목록이나 게시판 제목처럼 답이 오지 않는 문서도 많기 때문입니다.

다만 이 차이가 늘 극적이지는 않습니다. 같은 실험에서 리눅스 명령어 질문을 그대로 넣었을 때는 베이스 모델도 "`ls` 명령어입니다"라고 바로 답했습니다. 요즘 사전학습 데이터에는 질문과 답이 짝을 이룬 글도 많이 섞여 있어서, 베이스 모델도 상황에 따라 답처럼 보이는 글을 이어 씁니다. 차이는 그 행동을 믿고 기대할 수 있느냐에 있습니다.

## 2단계 지도 파인튜닝: 모범 답안으로 답하는 법 익히기

베이스 모델에 "질문을 받으면 답을 한다"는 습관을 들이는 단계가 지도 파인튜닝입니다. 흔히 SFT라고 부르며, 지시를 따르도록 가르친다는 뜻에서 인스트럭션 튜닝이라고도 합니다. 방법은 단순합니다. 질문과 그 질문에 대한 모범 답안을 짝지은 데이터를 준비해, 모델이 모범 답안을 그대로 따라 쓰도록 학습시킵니다.

> **용어 풀이**
>
> - **SFT(Supervised Fine-Tuning, 지도 파인튜닝):** 입력과 바람직한 출력의 짝을 정답으로 주고 모델을 추가 학습하는 방법입니다. LLM에서는 주로 질문과 모범 답안의 짝을 씁니다.
> - **인스트럭션 튜닝(Instruction Tuning):** 지시문과 그에 맞는 응답으로 모델을 학습해, 사용자의 지시를 따르는 모델로 만드는 파인튜닝입니다.

InstructGPT 논문에서는 Upwork와 Scale AI를 통해 모은 약 40명의 작업자가 이 모범 답안을 직접 썼습니다. SFT 데이터는 약 13,000개의 프롬프트로, 실제 API 사용자들이 보낸 프롬프트와 작업자가 직접 만든 프롬프트를 함께 썼습니다. Qwen2.5 기술 보고서는 100만 개가 넘는 예시로 SFT를 했다고 밝힙니다.

학습 방식 자체는 사전학습과 같은 다음 토큰 예측입니다. 달라지는 것은 무엇을 맞히게 하느냐입니다. Hugging Face의 학습 라이브러리 TRL 문서(1.17.1 기준)를 보면, SFT의 손실은 사전학습과 같은 토큰 단위 교차 엔트로피이고, 질문(prompt)과 답(completion)이 나뉜 데이터를 쓰면 기본값으로 답 부분의 토큰에서만 손실을 계산합니다. 질문을 따라 쓰는 연습은 빼고, 질문을 본 뒤 답을 쓰는 연습만 시키는 셈입니다.

> **용어 풀이**
>
> - **손실(Loss)·교차 엔트로피(Cross-entropy):** 손실은 모델의 예측이 정답에서 얼마나 벗어났는지 나타내는 값이고, 학습은 이 값을 줄이는 방향으로 파라미터를 고칩니다. 교차 엔트로피는 정답 토큰에 모델이 준 확률이 낮을수록 커지는 손실 계산 방법입니다.
> - **TRL(Transformer Reinforcement Learning):** Hugging Face가 만든 LLM 후속 학습 라이브러리입니다. SFT, 보상 모델 학습, DPO 등의 학습 도구를 제공합니다.

이때 대화는 채팅 템플릿으로 바뀐 글의 형태로 모델에 들어갑니다. 앞의 실험에서 Qwen2.5-0.5B-Instruct의 채팅 템플릿이 만든 글을 그대로 출력해 보면 다음과 같습니다.

```text
<|im_start|>system
You are Qwen, created by Alibaba Cloud. You are a helpful assistant.<|im_end|>
<|im_start|>user
리눅스에서 현재 폴더의 파일 목록을 보는 명령어는 무엇인가요?<|im_end|>
<|im_start|>assistant
```

시스템 안내, 사용자 질문, 어시스턴트의 차례가 `<|im_start|>`와 `<|im_end|>`라는 특별한 토큰으로 구분됩니다. 시스템 안내 문장은 사용자가 따로 주지 않으면 템플릿이 기본값으로 넣은 것입니다. 모델은 마지막 줄 `assistant` 다음에 올 글을 이어 쓰게 되고, SFT를 거친 모델은 이 자리에서 답을 쓰다가 답이 끝나면 `<|im_end|>`를 내놓도록 배웠습니다. 실제로 실험에서 Instruct 모델은 답을 마친 뒤 `<|im_end|>`로 멈춘 경우가 있었지만, 베이스 모델은 대화 형식의 네 질문 모두에서 이 토큰을 내놓지 못하고 80토큰 한도까지 같은 말을 반복했습니다. [지난 글](https://stackguide.route50.kr/posts/how-llm-writes-tokens-261113/)에서 본 프롬프트 템플릿이 바로 이 틀이며, 채팅 서비스는 이런 감싸기를 사용자 몰래 해 주고 있었던 셈입니다.

> **용어 풀이**
>
> - **특별 토큰(Special Token):** 일반 글자가 아니라 대화의 시작과 끝, 역할 구분 같은 구조 정보를 나타내려고 어휘에 따로 넣어 둔 토큰입니다.

### SFT가 가르치는 것은 지식보다 형식에 가깝다

SFT 데이터는 사전학습 데이터보다 훨씬 작습니다. 2023년 발표된 LIMA 논문은 극단적인 실험을 했습니다. 65B 크기의 LLaMA 모델을 강화학습이나 선호 학습 없이, 정성 들여 고른 1,000개의 질문·답변 쌍으로만 SFT했더니 특정 응답 형식을 잘 따르고 학습 데이터에 없던 작업에도 일반화했습니다. 연구진은 이를 근거로 "LLM의 지식은 거의 다 사전학습에서 배우며, 원하는 출력을 내도록 가르치는 데는 적은 인스트럭션 튜닝 데이터로 충분하다"는 해석을 내놓았습니다. 모든 연구자가 동의하는 결론이라기보다는 하나의 가설이지만, 단계별 역할을 이해하는 데는 쓸모 있는 관점입니다.

비유하면 SFT는 많이 아는 신입 직원에게 모범 응대 사례집을 보여 주는 일에 가깝습니다. 사례집을 익히면 손님을 맞는 말투와 순서는 금방 배우지만, 원래 몰랐던 업무 지식이 생기지는 않습니다. 표 1에서 Instruct 모델이 답변 형식은 갖췄지만 비밀번호 저장 방법을 틀리게 설명한 것도 같은 맥락으로 볼 수 있습니다. 실험 중에는 Docker 질문에 한국어 대신 중국어로 답한 경우도 있었는데, 작은 모델이 형식은 따라 해도 세부 지시까지 지키지는 못하는 모습입니다.

## 3단계 RLHF: 사람이 더 좋아하는 답 쪽으로 다듬기

SFT만으로도 대화는 됩니다. 그런데 모범 답안을 사람이 일일이 쓰는 데는 시간과 비용이 많이 들고, 좋은 답이란 무엇인지를 모범 답안 몇 개로 다 보여 주기도 어렵습니다. 같은 질문에도 더 정확한 답, 더 간결한 답, 해로운 내용을 피한 답처럼 좋고 나쁨의 기준이 여러 가지이기 때문입니다.

그래서 RLHF는 사람에게 답을 쓰게 하는 대신 고르게 합니다. 요리 대회에 비유하면, 심사위원에게 한 접시에 몇 점인지 절대 점수를 매기라고 하면 사람마다 기준이 달라 들쭉날쭉하지만, 두 접시 중 어느 쪽이 더 나은지는 비교적 쉽게 일관되게 고릅니다. Hugging Face의 RLHF 해설 글도 같은 이유를 듭니다. 사람이 매긴 점수는 기준이 제각각이고 잡음이 많아서, 보통 같은 프롬프트에 대한 여러 답변의 순위를 매기게 한다는 것입니다.

InstructGPT 논문의 RLHF는 두 부분으로 이뤄집니다.

1. **보상 모델 학습:** SFT 모델이 같은 프롬프트에 대해 쓴 답변 4~9개를 작업자가 좋은 순서대로 순위를 매깁니다. 이 비교 데이터(약 33,000개 프롬프트)로, 프롬프트와 답변을 넣으면 "사람이 이 답을 얼마나 좋아할지"를 숫자 하나로 내놓는 보상 모델을 학습합니다. 논문은 보상 모델로 6B 크기의 모델을 썼습니다.
2. **강화학습:** 모델이 프롬프트(약 31,000개)에 답을 쓰면 보상 모델이 채점하고, PPO라는 강화학습 알고리즘으로 점수가 높아지는 방향으로 모델을 고칩니다. 이 과정을 계속 반복합니다.

> **용어 풀이**
>
> - **보상 모델(Reward Model):** 프롬프트와 답변을 받아 사람이 그 답을 얼마나 선호할지를 점수 하나로 예측하는 모델입니다. 사람 대신 수많은 답을 빠르게 채점하는 역할을 합니다.
> - **강화학습(Reinforcement Learning):** 정답을 직접 보여 주는 대신, 모델이 한 행동에 점수(보상)를 주고 점수가 높아지는 쪽으로 행동을 고쳐 나가게 하는 학습 방법입니다.
> - **PPO(Proximal Policy Optimization, 근접 정책 최적화):** 한 번에 모델을 너무 크게 바꾸지 않도록 제한하면서 보상을 높이는 강화학습 알고리즘입니다. 학습을 안정적으로 진행하려고 씁니다.

여기에는 한 가지 함정이 있습니다. 보상 모델은 사람의 취향을 흉내 낸 근사치일 뿐이어서, 모델이 보상 모델의 허점을 파고들면 점수는 높지만 사람이 보기에는 이상한 답이 나올 수 있습니다. Hugging Face의 해설 글은 아무 제약이 없으면 모델이 보상 모델을 속여 높은 점수를 받는 횡설수설을 만들어 낼 수 있다고 설명합니다. 그래서 InstructGPT는 강화학습 중인 모델이 원래의 SFT 모델과 토큰마다 얼마나 달라졌는지를 KL 발산으로 재서 벌점으로 뺍니다. 점수를 올리되 원래 모델에서 너무 멀리 가지는 말라는 목줄인 셈입니다.

> **용어 풀이**
>
> - **KL 발산(Kullback-Leibler Divergence):** 두 확률분포가 얼마나 다른지 나타내는 값입니다. 여기서는 학습 중인 모델과 원래 모델이 다음 토큰에 매기는 확률이 얼마나 달라졌는지를 재는 데 씁니다.

*(그림: 같은 질문에 대한 두 답변 중 A가 더 낫다는 선호 데이터가 두 갈래로 쓰이는 모습. 위쪽 RLHF 경로는 먼저 답변에 점수 하나를 매기는 보상 모델을 학습하고, PPO 강화학습으로 점수가 오르게 모델을 고치며, 모델이 쓴 답을 보상 모델이 반복해 채점하고 원래 모델과 멀어지면 KL 벌점을 줍니다. 아래쪽 DPO 경로는 보상 모델 없이 A의 확률은 높이고 B의 확률은 낮추도록 모델을 바로 학습합니다. 두 경로 모두 선호에 맞춘 모델로 이어집니다.)*

*그림 2. 선호 데이터를 모델에 반영하는 RLHF(PPO)와 DPO의 차이 (자료: InstructGPT·DPO 논문, Hugging Face RLHF 해설, 2026-11-13 확인)*

효과는 컸습니다. InstructGPT 논문에서 작업자들은 1.3B 크기의 InstructGPT 답변을 175B 크기의 GPT-3 답변보다 더 선호했습니다. 파라미터가 100배 넘게 적은 모델이 이긴 것입니다. 같은 175B 크기끼리 비교하면 InstructGPT의 답이 85±3%의 비율로 선호됐습니다. 비용은 사전학습보다 훨씬 적었습니다. 논문에 따르면 175B SFT 모델 학습에는 4.9 petaflop/s-day, 175B RLHF 모델 학습에는 60 petaflop/s-day가 들었는데, GPT-3 사전학습에는 3,640 petaflop/s-day가 들었습니다.

> **용어 풀이**
>
> - **petaflop/s-day(페타플롭스-일):** 초당 1페타(10¹⁵)번의 연산을 하루 동안 계속한 만큼의 계산량입니다. 학습에 든 계산량을 비교하는 단위로 씁니다.

대가도 있었습니다. RLHF를 거친 모델은 일부 공개 자연어 처리 시험(SQuAD, DROP, HellaSwag 등)에서 GPT-3보다 점수가 떨어졌고, 논문은 이를 "정렬 세금(alignment tax)"이라고 불렀습니다. 연구진은 강화학습 중에 사전학습 데이터로 하는 학습을 섞는 방법(PPO-ptx)으로 이 하락을 크게 줄였습니다. 또 논문은 이렇게 맞춘 기준이 넓은 의미의 "인류의 가치"가 아니라 특정 작업자들과 연구진의 선호라는 점도 분명히 밝힙니다.

> **용어 풀이**
>
> - **AI 정렬(AI Alignment):** AI가 사용자의 의도와 사람이 바라는 가치에 맞게 행동하도록 만드는 일입니다. RLHF는 대표적인 정렬 방법입니다.

### RLHF만 있는 것은 아니다: DPO와 AI 피드백

PPO를 쓰는 RLHF는 보상 모델을 따로 학습하고, 강화학습 중에 모델이 답을 계속 생성하며 채점받아야 해서 복잡하고 불안정해지기 쉽습니다. 2023년 발표된 DPO는 이 과정을 줄였습니다. 같은 비교 데이터를 쓰되, 보상 모델과 강화학습 없이 "선호된 답의 확률은 높이고 선호되지 않은 답의 확률은 낮추는" 단순한 분류 문제처럼 모델을 바로 학습합니다. 논문은 이 방법이 PPO 기반 RLHF와 같거나 더 나은 결과를 냈다고 보고합니다.

> **용어 풀이**
>
> - **DPO(Direct Preference Optimization, 직접 선호 최적화):** 보상 모델과 강화학습 단계를 거치지 않고, 선호 비교 데이터로 모델을 직접 학습하는 방법입니다.

실제 대형 모델도 이런 변형을 씁니다. Llama 3는 SFT와 DPO를 한 묶음으로 여섯 번 반복했고, SFT 데이터 일부는 모델이 쓴 여러 답 중 좋은 것을 골라 만드는 리젝션 샘플링으로 마련했습니다. 보고서는 PPO도 시험했지만 DPO가 큰 모델에서 계산이 덜 들고 지시 따르기 평가에서 더 좋았다고 설명합니다. Qwen2.5는 SFT 뒤에 여러 단계의 강화학습을 거쳤다고 밝힙니다.

> **용어 풀이**
>
> - **리젝션 샘플링(Rejection Sampling, 거부 표집):** 모델이 한 질문에 여러 답을 쓰게 한 뒤, 기준에 맞는 좋은 답만 남기고 나머지는 버리는 방법입니다. 남긴 답은 다음 학습 데이터로 씁니다.

사람 대신 AI가 비교를 맡기도 합니다. Anthropic이 2022년 발표한 Constitutional AI 논문은 사람이 쓴 원칙 목록(헌법)을 주고, 모델이 스스로 답을 비판하고 고쳐 쓰게 한 뒤, 두 답 중 어느 쪽이 나은지도 AI가 판단하게 했습니다. 이 판단으로 학습한 선호 모델을 보상으로 쓰는 방식을 RLAIF라고 부릅니다.

> **용어 풀이**
>
> - **RLAIF(Reinforcement Learning from AI Feedback, AI 피드백 기반 강화학습):** 사람 대신 AI 모델이 답변을 비교·평가하고, 그 평가를 보상으로 삼아 강화학습하는 방법입니다.

그래서 오늘날 "RLHF"라는 말은 사람이나 AI의 선호를 반영하는 이 마지막 단계 전체를 느슨하게 가리키는 경우가 많습니다. 어떤 회사가 어떤 조합을 쓰는지는 공개된 보고서마다 다르고, 상용 서비스 대부분은 정확한 방법을 공개하지 않습니다.

## 이 과정을 알고 나면 보이는 것들

**모델 이름의 `Base`와 `Instruct`.** 오픈 모델을 내려받다 보면 같은 이름에 `-Base`, `-Instruct`, `-Chat` 같은 꼬리가 붙은 판이 여럿 있습니다. 대화나 질문 답변에 쓸 것이라면 후속 학습을 거친 `Instruct`·`Chat` 판을 고르는 것이 기본입니다. 베이스 판은 표 1처럼 대화에 서툴지만, 자기 데이터로 처음부터 파인튜닝하려는 경우에는 출발점으로 쓰입니다. 어느 판인지는 모델 카드에 적힌 학습 단계에서 확인할 수 있습니다.

**지식의 한계는 후속 학습으로 잘 메워지지 않는다.** LIMA의 해석처럼 지식이 주로 사전학습에서 온다면, 사전학습 데이터에 없던 최신 정보나 드문 사실은 후속 학습을 거쳐도 모델이 정확히 알기 어렵습니다. 여기에 RLHF는 사람이 좋아하는 답 쪽으로 모델을 기울이므로, 모르는 내용도 자신 있고 매끄러운 문장으로 쓰는 일이 생깁니다. 이렇게 사실이 아닌 내용을 그럴듯하게 만들어 내는 현상을 환각이라고 합니다. 표 1의 비밀번호 답처럼 형식이 깔끔한 답일수록 내용을 원문으로 확인하는 습관이 필요합니다.

> **용어 풀이**
>
> - **환각(Hallucination):** LLM이 사실과 다르거나 근거 없는 내용을 그럴듯한 문장으로 만들어 내는 현상입니다.

**말투와 거절에도 학습의 흔적이 있다.** 대화형 모델이 공손하게 말하고, 목록과 굵은 글씨로 정리하고, 어떤 부탁은 거절하는 것은 SFT의 모범 답안과 선호 학습의 평가 기준이 반영된 결과로 볼 수 있습니다. 같은 베이스 모델이라도 어떤 데이터와 기준으로 후속 학습했느냐에 따라 성격이 꽤 다른 어시스턴트가 됩니다.

**내 데이터로 모델을 고치고 싶다면 대개 파인튜닝부터.** 사전학습은 수천~수만 개의 GPU와 수조 개의 토큰이 필요해 개인이나 작은 팀이 시도하기 어렵습니다. 특정 업무에 맞춘 모델이 필요하면 공개된 모델을 출발점으로 SFT를 하는 것이 일반적이고, Google의 머신러닝 강좌가 소개하는 것처럼 파라미터 일부만 고치는 효율적인 파인튜닝 방법을 쓰면 필요한 자원을 더 줄일 수 있습니다. 다만 앞의 실험처럼 파인튜닝은 형식과 행동을 바꾸는 데 강하고 새 지식을 넣는 데는 한계가 있으니, 목적이 최신 정보나 사내 문서를 답에 반영하는 것이라면 다른 방법과 비교해 보고 고르는 편이 좋습니다.

정리하면 LLM은 세 번 배웁니다. 사전학습에서 세상의 글로 언어와 지식을 익히고, 지도 파인튜닝에서 질문에 답하는 형식을 배우고, 선호 학습에서 사람이 더 좋아하는 답 쪽으로 다듬어집니다. 오늘 쓰는 채팅 서비스의 답 하나하나에는 이 세 단계가 겹쳐 있습니다. 같은 크기의 모델이 베이스판과 Instruct판에서 얼마나 다르게 행동하는지 직접 보고 싶다면, 위의 코드에서 질문만 바꿔 실행해 보세요.
